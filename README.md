# RH-NBV: Receding-Horizon Next-Best-View Planning for Targeted Plant Perception

Planner and experiment code for a **receding-horizon next-best-view (NBV)**
strategy that drives a **UR5e** arm with a wrist-mounted **Intel RealSense L515**
depth camera to reconstruct targeted objects (a plant node, fruit, or mug)
under partial occlusion. The planner reasons over a short horizon of candidate
viewpoints and re-plans after each move, trading off information gain against
reachability and a minimum standoff distance.

This repository holds the planners, the simulation/experiment harness, and the
analysis scripts. The ROS 2 robot description, MoveIt 2 configuration, and
Gazebo worlds live in the companion repository
[**ur5e-l515-ros2**](https://github.com/ays3gul/ur5e-l515-ros2).

> M.Sc. thesis work. The **GradientNBV** planner is included as a baseline and
> follows Burusa et al., *"Gradient-based Local Next-Best-View Planning for
> Improved Perception of Targeted Plant Nodes"*, IEEE ICRA 2024.

---

## Planners

Four viewpoint planners share the same perception stack, scene representation,
and evaluation metrics, so they can be compared head-to-head:

| `PLANNER` | Method                                  | Entry point                     |
|-----------|-----------------------------------------|---------------------------------|
| `rh`      | **RH-NBV** — receding-horizon NBV (ours)| `test_rh_node.py`               |
| `gradient`| GradientNBV baseline (ICRA 2024)        | `test_gradient_node.py`         |
| `pso`     | Particle-swarm optimization baseline    | `test_baseline_node.py`         |
| `random`  | Random-sampling baseline                | `test_baseline_node.py`         |

All planners enforce the same fair-comparison constraints — a shared camera
workspace box, a common minimum standoff (`CAM_MIN_STANDOFF`), and identical
F1 scoring with panel/occluder voxels excluded — so differences reflect the
planning strategy, not the search bounds.

## Targets and occlusion scenarios

- **Targets** (`TARGET`): `bunny` (default), `mug`, `tomato`, plus a tree
  scenario via `run_tree.sh`.
- **Occlusion** (`OCC`): `none`, `frontal`, `half_box`, `tunnel`, `well`, and
  staged panel walls `panels1..8`. Panel worlds are generated by
  `make_panel_world.py` (see `SETUP.md` for the staging semantics).

## Requirements

- **Ubuntu 24.04** + **ROS 2 Jazzy**
- **Gazebo (Gz Sim)** via `ros-jazzy-ros-gz`, **MoveIt 2**
- **conda** environment `rh_nbv_ros2` (`environment.yml`) — PyTorch + CUDA for
  the segmentation network
- An NVIDIA GPU (~8 GB VRAM) for the perception model

## Installation

Full fresh-machine instructions are in [`SETUP.md`](SETUP.md). In short:

```bash
# 1. ROS 2 apt dependencies
sudo apt update
sudo apt install -y ros-jazzy-ur ros-jazzy-ur-simulation-gz \
  ros-jazzy-ur-moveit-config ros-jazzy-realsense2-description \
  ros-jazzy-ros-gz ros-jazzy-moveit

# 2. Clone both repositories
git clone https://github.com/ays3gul/ur5e-l515-ros2.git ~/ros2_ws/src
git clone https://github.com/ays3gul/recedinghorizon-ros2.git ~/Desktop/RecedingHorizon

# 3. Build the colcon workspace
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build
source install/setup.bash

# 4. Create the conda environment
conda env create -f ~/Desktop/RecedingHorizon/environment.yml
conda activate rh_nbv_ros2
```

## Running (simulation)

The system runs as **two terminals**: the robot + Gz Sim stack, and the planner.

### Terminal 1 — simulation + robot stack

```bash
# Kill any stale sim/ROS processes from a previous run
pkill -9 -f "gz sim"; pkill -9 -f "ros2 launch"; pkill -9 -f parameter_bridge
pkill -9 -f move_group; pkill -9 -f arm_control_node; pkill -9 -f test_baseline
sleep 2

source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
export GZ_SIM_RESOURCE_PATH=$GZ_SIM_RESOURCE_PATH:$HOME/ros2_ws/install/ur5e_l515_description/share

TARGET=mug OCC=panels5 ros2 launch ur5e_l515_description move_group_gz_ur5e.launch.py
```

Wait until the log prints **`arm_control_node ready — serving move_arm_to_pose`**
before starting the planner.

### Terminal 2 — planner

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash

cd ~/Desktop/RecedingHorizon
TARGET=mug OCC=panels5 PLANNER=rh NUM_TRIALS=5 EXPERIMENT=C ./run_ros2_gz.sh
```

Keep `TARGET` and `OCC` **identical in both terminals** — Terminal 1 selects the
world, Terminal 2 must score against that same scene.

### Running on the real robot

Use `run_ros2_real.sh` (Terminal 2) together with `real_ur5e.launch.py`
(Terminal 1) instead of the Gz variants. See `SETUP.md` for the D455 remap and
HSV calibration (`hsv_test.py`).

## Environment variables

| Variable          | Values / default                                   | Meaning |
|-------------------|----------------------------------------------------|---------|
| `PLANNER`         | `rh` (default), `gradient`, `pso`, `random`        | Which planner to run |
| `TARGET`          | `bunny` (default), `mug`, `tomato`                 | Object to reconstruct |
| `OCC`             | `none`, `frontal`, `half_box`, `tunnel`, `well`, `panels1..8` | Occlusion scenario |
| `EXPERIMENT`      | label, e.g. `C`, `D`                               | Tag written into the results directory |
| `NUM_TRIALS`      | integer                                            | Repeated trials per configuration |
| `RH_K`, `RH_H`    | integers                                           | RH-NBV candidate count / horizon depth |
| `CAM_HW`          | `"x,y,z"` (default `0.35,0.10,0.22`)              | Camera-workspace halfwidths |
| `CAM_WRAP_Y`      | float (default `0.60`)                             | Extra −Y extension so side views are searchable |
| `CAM_MIN_STANDOFF`| float (default `0.50`)                            | Minimum camera–target distance (all planners) |
| `RVIZ`            | `1` (default) / `0`                               | Launch RViz2 alongside the planner |
| `HEADLESS`        | `0` (default) / `1`                               | Run Gz Sim without the GUI |

## Experiments and analysis

- Batch runs (the "ladders" that sweep planners × occlusion stages) are driven by
  `run_ladder4.sh`, `run_tree_ladder.sh`, and `run_tree.sh`.
- Per-trial outputs land under `results/`.
- Aggregate and plot with `analyze_bunny_results.py`, `analyze_tree_results.py`,
  `plot_tree_curves.py`, and `plot_tree_curves_4p.py`.

The primary metric is **F1** over the reconstructed target surface (with
occluder/panel voxels excluded from scoring), complemented by coverage and
reconstruction-quality metrics in `metrics*.py`.
